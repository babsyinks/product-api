## Architecture

```
app/
├── Exceptions/
│   └── Handler.php              # Unified JSON error responses
├── Http/
│   ├── Controllers/Api/
│   │   ├── AuthController.php   # Register, Login, Logout, Me
│   │   └── ProductController.php
│   ├── Requests/
│   │   ├── StoreProductRequest.php
│   │   └── UpdateProductRequest.php
│   └── Resources/
│       └── ProductResource.php  # Transforms Product → JSON
├── Models/
│   ├── Product.php              # HasUuids, SoftDeletes, query scopes
│   └── User.php                 # HasApiTokens (Sanctum)
├── Policies/
│   └── ProductPolicy.php        # Authorization rules per action
└── Providers/
    └── AppServiceProvider.php   # Policy registration

database/
├── factories/
│   ├── ProductFactory.php       # Realistic fake data + states
│   └── UserFactory.php
├── migrations/                  # UUID PKs, soft deletes, indexes
└── seeders/
    ├── DatabaseSeeder.php
    └── ProductSeeder.php        # Seeds 100 products (mix of states)

routes/
└── api.php                      # /api/v1/... versioned routes
```

### Key design choices

- **UUID primary keys** — avoids sequential ID enumeration attacks.
- **Soft deletes** — products are never truly destroyed; recoverable.
- **Model scopes** (`search`, `priceRange`, `inStock`) — keeps controller lean and filter logic co-located with the model.
- **API Resources** — decouples the DB shape from the API contract; easy to version.
- **Form Requests** — validation and authorisation are separated from controller logic.
- **Unified error handler** — all `api/*` routes return consistent JSON errors regardless of exception type.
- **API versioning** — all routes live under `/api/v1/`, making future `/v2` non-breaking.

## Setup Instructions

### 1. Local setup (SQLite — zero config)

**Prerequisites:** PHP 8.2+, Composer

```bash
# Clone the repo
git clone https://github.com/babsyinks/product-api.git
cd product-api

# Install dependencies
composer install

# Environment
cp .env.example .env
php artisan key:generate

# SQLite database (default — no server needed)
touch database/database.sqlite

# Run migrations + seed 100 products (idempotent approach) - run in dev environment. Prefer `php artisan migrate --seed` in production
php artisan migrate:fresh --seed

# Start the dev server
php artisan serve
```

API is now live at **http://localhost:8000/api/v1**

---

### 2. Docker setup (MySQL)

**Prerequisites:** Docker, Docker Compose

```bash
git clone https://github.com/your-handle/product-api.git
cd product-api

cp .env.example .env
# Edit .env: set DB_CONNECTION=mysql, DB_HOST=db, DB_DATABASE=product_api, etc.

docker compose up -d --build

# First-time only: run migrations + seed inside the container
docker compose exec app php artisan key:generate
docker compose exec app php artisan migrate:fresh --seed # dev environment only (prefer `docker compose exec app php artisan migrate --seed` in production)
```

| Service    | URL                        |
|------------|----------------------------|
| API        | http://localhost:8000      |
| phpMyAdmin | http://localhost:8080 (dev profile only) |

To start phpMyAdmin: `docker compose --profile dev up -d`

## API Reference

### Base URL

```
http://localhost:8000/api/v1
```

All responses use `application/json`. Successful responses wrap data in a `data` key.

---

### Authentication

#### Register

```http
POST /api/v1/register
```

| Field                 | Type   | Required |
|-----------------------|--------|----------|
| name                  | string |        |
| email                 | string |        |
| password              | string |  min:8 |
| password_confirmation | string |        |

**Response 201:**
```json
{
  "token": "1|abc123...",
  "token_type": "Bearer"
}
```

---

#### Login

```http
POST /api/v1/login
```

| Field    | Type   | Required |
|----------|--------|----------|
| email    | string |          |
| password | string |          |

**Response 200:** same shape as register.

---

#### Logout

```http
POST /api/v1/logout
Authorization: Bearer {token}
```

**Response 200:** `{ "message": "Logged out successfully." }`

---

#### Me

```http
GET /api/v1/me
Authorization: Bearer {token}
```

**Response 200:** `{ "id": 1, "name": "...", "email": "..." }`

### Products

#### List products (paginated)

```http
GET /api/v1/products
```

**Query parameters:**

| Parameter | Type    | Default    | Description                              |
|-----------|---------|------------|------------------------------------------|
| search    | string  | —          | Full-text search on name + description   |
| min_price | number  | —          | Price ≥ value                            |
| max_price | number  | —          | Price ≤ value                            |
| in_stock  | boolean | —          | `true` = in stock only, `false` = OOS    |
| sort_by   | string  | created_at | `price`, `name`, `created_at`            |
| sort_dir  | string  | desc       | `asc` or `desc`                          |
| per_page  | integer | 15         | Results per page (1–100)                 |

**Response 200:**
```json
{
  "data": [
    {
      "id": "9c7e5b2a-...",
      "name": "Premium Headphones",
      "description": "High-fidelity over-ear...",
      "price": 99.99,
      "stock": 50,
      "in_stock": true,
      "created_at": "2024-01-01T00:00:00+00:00",
      "updated_at": "2024-01-01T00:00:00+00:00"
    }
  ],
  "links": { "first": "...", "last": "...", "prev": null, "next": "..." },
  "meta": { "current_page": 1, "from": 1, "last_page": 7, "per_page": 15, "to": 15, "total": 100 }
}
```

---

#### Create product

```http
POST /api/v1/products
Authorization: Bearer {token}
```

| Field       | Type    | Required |
|-------------|---------|----------|
| name        | string  |   max:255|
| description | string  | —        |
| price       | decimal |   min:0  |
| stock       | integer |   min:0  |

**Response 201:** single product wrapped in `data`.

---

#### Get product

```http
GET /api/v1/products/{id}
```

**Response 200:** single product wrapped in `data`.  
**Response 404:** `{ "message": "Product not found." }`

---

#### Update product

```http
PUT /api/v1/products/{id}
Authorization: Bearer {token}
```

All fields optional (PATCH-style). Send only what changes.

**Response 200:** updated product wrapped in `data`.

---

#### Delete product (soft)

```http
DELETE /api/v1/products/{id}
Authorization: Bearer {token}
```

**Response 200:** `{ "message": "Product deleted successfully." }`

The product is soft-deleted — it remains in the database with `deleted_at` set and is excluded from all public queries.

## Filters & Sorting

**Search by name:**
```
GET /api/v1/products?search=wireless
```

**Price range:**
```
GET /api/v1/products?min_price=10&max_price=500
```

**In-stock only, sorted by price ascending:**
```
GET /api/v1/products?in_stock=true&sort_by=price&sort_dir=asc
```

**Combined:**
```
GET /api/v1/products?search=headphone&min_price=50&in_stock=true&sort_by=price&sort_dir=asc&per_page=5
```

## Running Tests

```bash
# Run full test suite (uses in-memory SQLite automatically)
./vendor/bin/pest

# With coverage
./vendor/bin/pest --coverage

# Single file
./vendor/bin/pest tests/Feature/ProductControllerTest.php
```

The test suite covers:
- Guest access (list, show)
- Auth-gated actions (create, update, delete)
- Validation rules (required fields, min values)
- Search + filter + price range
- Soft delete verification
- 404 handling
- Auth register / login / logout
